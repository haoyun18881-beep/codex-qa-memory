# Codex QA 记忆存取入口

## 使用说明

- 这是一个空白 QA Memory 入口，新安装不会预置任何用户记忆或运行状态。
- 记忆节点保存在本目录；原始 QA 日记默认位于 `%USERPROFILE%\.codex\qa-diary`。
- CLI 先过滤、排序和解码，再返回当前问题需要的小节点。
- 自动维护只生成 `candidate（候选）` 和审计记录，不会直接提升 active。
- Skill 入口：`%USERPROFILE%\.codex\skills\codex-qa-memory\SKILL.md`。
- 需要原话、日期或会话编号时，再转 `codex-qa-diary-recall`。

## 阅读顺序

| 场景 | 先读 | 再读 |
| --- | --- | --- |
| 快速恢复 | `qa-mem.ps1 get -Mode quick` | 必要时查 `03-索引.md` 和命中节点所在 `records\YYYY-MM.md` |
| 查码表 | `01-码表.md` | `codex-qa-memory\references\codebook.md` |
| 写候选 | `02-模板.md` | `candidates\YYYY-MM.md` |
| 查维护报告 | `maintenance\YYYY-MM-DD.md` | `machine\audit.jsonl` |
| 审查提升/降级 | `codex-qa-memory\references\promotion-policy.md` | `03-索引.md`、`records\YYYY-MM.md` |

## 自然触发语

| 用户可能说 | 默认动作 |
| --- | --- |
| 咱们之前聊过、之前我们说过、以前说过 | 用 quick 档取回相关 active 节点和 candidate 历史主题；candidate 只作线索。 |
| 我们做过、咱们之前做的、之前怎么处理 | 取回任务状态、项目状态、失败经验和工具状态节点。 |
| 你还记得吗、之前定过、之前的规则/偏好 | 取回偏好、规则、决策节点；证据不足时转 `codex-qa-diary-recall`。 |

## 长期偏好存放边界

- 长期偏好默认存为本目录的小节点，路径是 `%USERPROFILE%\.codex\qa-memory`。
- QA 日记 `%USERPROFILE%\.codex\qa-diary` 是来源证据和原始记录，不是默认 active 偏好库。
- 全局 `AGENTS.md` 只放硬规则、红线和入口指向；普通偏好不写进全局文件。
- 不依赖 Codex 产品内置记忆；本目录是本机 QA memory 的可审计存取实现。
- 新偏好要提升 active，必须有用户明确口径或主线程复核，不自动凭一次对话长期生效。
- QA memory 采用 `candidate` / `soft-active` / `active` 三态；软记忆只作同 scope、带来源的参考证据。
- 跨项目默认只允许用户长期习惯、全局偏好、全局红线和通用执行策略；项目状态、临时授权和运行态状态不得跨项目默认触发。
- 独立每日摘要写入入口已删除；不再新写 `Main-Agent Summary`，旧摘要只作历史遗留线索。

## 取回档位

| 档位 | 场景 | 节点上限 | 字数上限 | 关系跳数 |
| --- | --- | --- | --- | --- |
| quick | 新窗口、压缩后接续、轻量偏好恢复 | 6 | 1200 | 1 |
| project | 继续项目、查当前边界、恢复下一步 | 15 | 3000 | 2 |
| deep | 冲突裁决、规则审查、方案复盘 | 40 | 8000 | 2 |

## 硬规则

- 当前用户指令和当前项目文件优先于 QA 记忆。
- 默认每次 QA 沉淀 0-3 个小节点，超过必须写理由。
- 自动抽取只进入 `candidate（候选）`，不得直接变成 active。
- `soft-active` 只能来自低风险白名单和 policy gate，不得覆盖当前用户指令、当前项目文件或 active 规则。
- 每日解释性摘要不再作为长期记忆入口；长期上下文以 active 小节点为准。
- 高影响规则、授权、安全、凭据、服务、发布、外部智能体真实生效区必须人工复核。
- 数字码和 0/1 标志只给 CLI/工具计算、过滤和排序；给 LLM 的输出必须带短中文解码，不给纯裸码串。
- 不写 key、token、cookie、Authorization、Bearer、private key、密码或完整私密配置值。

## 文件说明

| 文件 | 用途 |
| --- | --- |
| `01-码表.md` | 合并码表，供 LLM 快速查数字码含义。 |
| `02-模板.md` | 事件卡、小节点、关系边、取回包模板。 |
| `03-索引.md` | active / review_required / conflict / source_ref 短索引。 |
| `records\YYYY-MM.md` | 已采纳或已确认的事件卡、小节点和关系边。 |
| `candidates\YYYY-MM.md` | 只读原型或自动抽取产生的候选，候选不等于 active。 |
| `maintenance\YYYY-MM-DD.md` | 按日期生成的自动维护报告，记录候选、terms、校验结果和脚本状态。 |
| `machine\*.jsonl` | JSONL 机器状态层，包含 nodes / edges / events / sources / audit / terms。 |

## 脚本

```powershell
powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\.codex\skills\codex-qa-memory\scripts\qa-mem.ps1" get -Mode quick
powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\.codex\skills\codex-qa-memory\scripts\qa-mem.ps1" validate
powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\.codex\skills\codex-qa-memory\scripts\qa_memory_recall.ps1" -Mode quick
powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\.codex\skills\codex-qa-memory\scripts\qa_memory_maintain.ps1" -Date (Get-Date -Format yyyy-MM-dd)
powershell -ExecutionPolicy Bypass -File "%USERPROFILE%\.codex\skills\codex-qa-memory\scripts\qa_memory_validate.ps1"
```
