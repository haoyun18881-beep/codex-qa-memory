# 写入策略

## 什么时候生成候选

必须生成候选：

- 用户说“记住”“以后都按这个”“不要再这样做”“这是规则”。
- 用户给出长期偏好、工作方式、输出风格、工具边界、授权边界或安全禁令。
- 项目稳定事实变化，例如项目名、核心目录、协议、五层治理结构、关键索引。
- 反复失败模式、排错结论、已验证修复路径。
- 旧口径被新口径替换。
- 用户否决、撤回、纠正某方案。

只进短期记录，不进长期 active：

- 一次性任务结果。
- 临时路径。
- 单轮命令输出。
- 当天状态。
- 无复用价值的讨论过程。

## 默认节点数

| 情况 | 默认节点数 |
| --- | --- |
| 无长期价值 | 0 |
| 单条用户偏好或小规则 | 1 |
| 一个明确裁决含多个边界 | 1-3 |
| 高影响规则、授权、安全、跨项目决策 | 可超过 3，但必须主线程写理由 |

## 状态提升

| 目标状态 | 通过条件 |
| --- | --- |
| candidate | 自动抽取，有来源指针 |
| soft-active | 低风险稳定偏好，未冲突 |
| active | 用户确认、项目文件落地、主线程采纳或多次复用 |
| review_required | 涉及授权、安全、凭据、服务、发布、外部智能体真实生效区 |
| superseded | 有明确新口径覆盖旧口径 |
| rejected | 用户或主线程明确否决 |
| archived | 长期不命中，或项目结束，仅追溯 |

## 写入 Gate

- 小节点只表达一件事。
- 小节点必须挂事件卡。
- 每个节点必须有来源指针。
- 每个节点必须有类型码、状态码和作用域码。
- 每个数字码必须有短中文标签：`type_label`、`status_label`、`scope_label`；关系边还要有 `rel_label`。
- 数字码只写字段，不做深层路径。
- 0/1 标志只由工具/CLI 计算并写入机器层；LLM 不输出纯 0/1 裸串作为主结论。
- 冲突必须显式标出，不静默合并。
- 不输出凭据原文。
- source 表必须能解析 `source_ref`；不可解析时只能写 `candidate` 或 `review_required`。
- 跨项目默认生效只允许用户长期习惯、全局偏好、全局红线和通用执行策略。
- 项目状态、临时授权、运行态工具/服务状态必须绑定具体 `scope_id`，不得写成全局 active。

## v2 写入路径

1. LLM 只生成候选内容、中文标签、来源指针和风险说明。
2. CLI 计算 0/1 标志、数字码一致性、三态 gate、跨项目 gate 和 source gate。
3. Markdown 审计层写事件卡/小节点/关系边，供主线程复核。
4. JSONL 机器状态层写结构化镜像：`events.jsonl`、`nodes.jsonl`、`edges.jsonl`、`sources.jsonl`。
5. `active`、高影响规则、授权、安全、服务、发布和外部智能体真实生效区相关内容必须由主线程或用户确认后才能生效。

不得让脚本输出成为无法审计的唯一事实来源；Markdown 审计层和 source 表必须能解释机器层每个可取回节点。
